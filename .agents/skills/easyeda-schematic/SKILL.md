# 脚本化绘制 EasyEDA Pro 原理图

## 什么时候用

- 要把一页原理图**从零画出来**，或按评审意见**整块重画**；
- 要**程序化核对**连接（网表比对），而不是靠肉眼；
- 希望图和代码一起进 git（`.eprj3` 是逐行 JSON 纯文本）。

## 前置检查（缺一不可）

1. 桌面客户端在运行，`doctor` 返回 `connected: true`。
2. 工程是 `.eprj3` 文件夹格式。**`.epro2` 不行**：`open --path` 只认
   `.eprj/.eprj2/.eprj3/.elib`，传 `.epro2` 会被静默忽略，只开出空白编辑器
   （`getReadyState()` 返回 `notLoaded`）。
3. 打开工程并拿到 session：

```powershell
& 'C:\Program Files\lceda-pro\lceda-pro.exe' open --path '<仓库>/x.eprj3'
# → {"ok":true,"data":{"sessionId":"<SESSION>"}}
```

4. 目标图页已打开并激活。注意 `dmt_Project.getCurrentProjectInfo()` 读的是
   **最后获得焦点的文档**，`open` 工程本身不激活任何文档。

## 执行方式

大脚本走 `--code-file`（`--code` 有 ~32KB 命令行上限），返回统一 JSON：

```powershell
& 'C:\Program Files\lceda-pro\lceda-pro.exe' invoke --session <SESSION> `
    --code-file '<仓库>/scripts/build-xxx.js' --timeout 240000
```

**`ok:true` 只代表代码跑完**。业务成败必须看返回的 `value`：
`steps`（错误累积）、`check.nets`（网表）、`check.err`。

## 一次只画一块（最重要的流程约束）

**不要试图一次性生成整页。** 人类画原理图也是一块一块来的，脚本也不例外。
一次性铺满的失败方式是：排版错 → 网表错 → 你却分不清是「布线逻辑错」还是「几何撞了」，
因为两者叠在一张图上。按块推进时，错误有唯一的可归因位置。

推荐节奏，每块都跑完这三步再进下一块：

1. **只放这一块的器件 + 连线 + 端口**，其它块不出现；
2. **跑网表**：这一块的期望表逐网络比对，`mismatched` 必须为空、`unnamed` 必须为空；
3. **截图读图**：确认无重叠、端口带名字、框包住内容。

一块稳定后再加下一块；全部放齐后**整页再核一次**（跨块网络会在这时才连起来）。

配套做法：

- 每块写成独立函数（`buildBlockA()`…），共享同一套 helper，主脚本按顺序调用；
- 图页每次重建都**新建并删除旧页**，避免旧图元/旧网络标签残留（`createNetLabel` 建的标签
  不在 `sch_PrimitiveAttribute` 的集合里，wipe 掉不掉，会永远飘在图上）；
- 排布坐标先写进 `docs/schematic-layout-plan.md`，用实测 bbox 算，不靠目测。


不要在没搞清楚几何语义的情况下一次性铺满整页。按顺序先测三件事，拿到数字再排版：

1. **端口语义**：`createNetPort` 的锚点是否就是传入坐标、四个 rotation 各自的朝向、
   名字文字渲染在锚点哪一侧、端口包围盒尺寸。测法：导线端点接端口 → 读 netlist 确认连通 → 截图看字落在哪。
2. **符号尺寸**：用 `lib_Symbol.getGeometry(symbolUuid, libraryUuid)` 拿到 `fullBBox`/`bodyBBox`/`pins`，
   得到每个器件的实际占位、引脚在哪几条边、同边引脚间距。**并排器件中心距按 fullBBox 取最大值**。
3. **密集扇出**：拿最坏情况（17 脚、同边间距 10）实测几种方案，确定「端口之间最小不重叠间距」
   和「一侧最多能放几个端口」，再决定是否需要合并同网络端口 / 旋转器件 / 拆页。

这三件事都可以派 subagent 并行做，但每个 subagent 必须在**自己新建的图页**上操作，
并在每次操作前用 `dmt_SelectControl.getCurrentDocumentInfo()` 确认当前文档是自己的页（会被抢焦点，需要重试）。
共用同一个编辑器 session，并发写同一页必然互相破坏。


### 1. 功能分区
每块一个矩形框 + 左上角标题，标题放在框**外**上方（`y = frameTop + 28`），避免压线。

### 2. 电源和地：逐脚打符号
**不要**把同一网络的引脚拉到一条汇总线再打一个符号。每个接 VBAT 的引脚插一个 VBAT 符号，
每个 GND 引脚插一个地符号——多个同名符号自动属于同一网络。

```
Power 符号 rotation 0  → 引脚在下方（向上引出的线头接它）
Power 符号 rotation 180→ 引脚在上方（向下引出的线头接它）
Ground 符号 rotation 0 → 引脚在上方（向下引出的线头接它）
```

### 3. 信号：就近连接，不要长总线
同网络的引脚竖直拉到一条水平总线上会让竖直通道随器件数爆炸，必然互相穿越。
正确做法：相邻器件之间走最短折线；跨区信号用网络标签。

### 4. 悬空线头接端口，不是网络标签
**用 `createNetPort('IN'|'OUT'|'BI', net, x, y, rotation, false)`，不要用 `createNetLabel`。**
端口是带方向的图元，`createNetLabel` 只是没有电气方向性的文字标签。

**朝向必须跟导线进入方向匹配，而且 `IN` 与 `OUT/BI` 是镜像的（同一 rotation 朝向相反）：**

```js
const ROT_IN  = { R: 0,   D: 90,  L: 180, U: 270 };  // side = 导线从锚点哪侧进来
const ROT_OUT = { R: 180, D: 270, L: 0,   U: 90  };  // OUT/BI 用这张
```

| 类型 | rot | 本体在锚点 | 文字在 | 导线从 |
|---|---|---|---|---|
| IN | 0 / 90 / 180 / 270 | 左 / 上 / 右 / 下 | 同侧 | 右 / 下 / 左 / 上 |
| OUT·BI | 0 / 90 / 180 / 270 | 右 / 下 / 左 / 上 | 同侧 | 左 / 上 / 右 / 下 |

导线从错误一侧进入，端口本体和网名就会压在那根线上（甚至被相邻器件盖住）——这是「端口压线」的唯一成因。

**`OUT` / `BI` 默认不显示网名，`IN` 默认显示。** 不显式打开就会出现「端口没名字但网络是对的」：

```js
await eda.sch_SourcePrimitiveComponent.updateAttribute({
  projectId, schematicName, pageName, primitiveId: portId,
  key: 'Name', valueVisible: true, keyVisible: false,
});
```

端口尺寸：本体 40×10，文字近端 45~50 + 3.7/字符。间距：正面相对 ≥180，同向单排 ≥120。
详见 `references/ports.md`。

### 5. 每个网络都必须有名字
netlist 里出现 `$2N14` 这种匿名网络，说明该网络没有任何命名锚点。
对策：每个网络至少有一个端口或符号；两脚直连的内部网络也要从共享端点分一支出去接端口。

### 6. 不许重叠（图元 / 文字 / 导线三者之间）
- 器件之间留够间距（引脚间距 10 单位时，符号上下各约 20 单位，横向至少 150 单位）；
- 通道（lane）间距 ≥ 40，端口本身宽约 30，18 会叠在一起；
- 分区框要包住所有内容，标题放框外上方；
- **验收靠看图和算包围盒，不靠感觉**。

### 7. 扇出：只有一种方案零缺陷
**竖排端口列（S3）**：每个引脚「水平引出 → 竖直通道 → 端口」，端口竖成一列、落在引脚块之外，
节距 20（下限 12），每个端口上方留 **60 单位尾段**给网名文字。这样 0 重叠、0 文字压线、0 导线交叉，
而且非交叉性可证（外层通道的任何水平段都到不了内层引脚）。

三种**已实测失败**的做法，别重犯：

- 交错引出（24/40）：交错量 16 < 端口宽 31 → 17 处相交、净距 −1；
- 同网络一条竖直通道：GND/VBUS 这类包住中间引脚的网络，主干必然横穿被夹住的其它 6 个网络（20 处交叉）；
- 端口正上方不留尾段：导线自带的网名标签正好压在端口体上（9 处）。

关键数字：端口体 **31×11**；竖排最小节距 **12**、横排 **32**（竖排省 2.6 倍）；
17 脚一侧 8 个端口只需 **205.5** 宽，而 A4 有 1169 —— 画布从来不是瓶颈。
详见 `references/fanout.md`。

### 8. 端口一律用 BI
`exp-port` 与 `exp-fanout` 对「IN/OUT 在 rot 180 是否镜像」结论不一致（一方说镜像、一方实测不镜像且会盖住
自己导线最后 10 单位）。**本项目统一用 `BI`**，朝向只按导线进入侧选；正式排版前先用 2 个端口 + 2 根线做
一次小验证（连通 + 文字不被压）再放大规模。

### 9. 截图必须自证新鲜度
`getCurrentRenderedAreaImage` 抓的是最后合成帧，窗口被遮挡时会**一直返回同一张旧图**
（实测连续 4 次重试、3 次重建都是同一张 53503 字节）。
抓图后换一次缩放/视图再抓，两张必须不同；或改用 `sch_Document.renderRegion({region,width,format})`
（页坐标、指定宽度、可标定）。

### 8. 坐标一律取整
竖放器件读回的引脚 y 可能是 `359.99999999999994`，直接画"垂直"线会变成微斜线，
`create` 返回 undefined；若那段恰好挂着网络名，网络会退化成匿名 `$1Nnnn`。
`Math.round()` 所有坐标。

### 8. 零长度线段会被拒绝
同高度两个引脚之间画"垂直"段即 `x1===x2 && y1===y2`，`create` 抛 `create failed!`。
建线前判掉，并确保网络名落在**第一段有效线段**上。

## 运行时故障与对策（都实测过）

| 现象 | 原因 | 对策 |
|---|---|---|
| `create failed!` / `create` 返回 undefined，**同一根线单独跑却成功** | 连续快速创建时编辑器的网络合并逻辑冲突 | 重试 3–4 次、间隔 200–400ms；两步 op 之间留 120ms |
| `sch_Netlist.getNetlist()` 返回空（长度 0），截图也一直是同一张 | 窗口长时间被遮挡/最小化，渲染与网表层停摆 | `lceda-pro activate` 提到前台；仍不行就 `session close --session <SID> --destroy` 后重新 `open --path` |
| 地符号盖住相邻引脚 | Ground 符号本体从锚点**向下延伸约 25 单位**，而多脚 IC 引脚间距只有 10 | 先**横向离开器件 ≥50 单位**再向下，让符号落在引脚区外 |
| 网络名出现两份（竖排+横排） | 折线每段都传了网络名 | 只给**第一段**传，整组继承 |
| 端口压住引脚/相邻端口 | 端口体 31×11，引脚间距只有 10 | 端口竖排节距 ≥12（建议 20）；AO3401 这类 40×40 小封装四周留 ≥50 净空 |
| 位号被静默改号 | 与工程已有位号冲突 | 建页后 `modify(id,{designator})` 显式设定，并立即回读校验 |

## 器件选择：必须精确名

器件搜索是模糊匹配，`'10K 0603'` 会命中 `PX9210K`（100+ 脚 BGA），`'1K'` 会命中接线端子。
用 `.name === '1k'`（注意这个库里有大小写混写，如 `10K`、`1k`、`100k`、`100uf`）精确匹配，
放置后立刻回读引脚数与引脚名做校验。

常用（本机实测存在）：`TYPE-C-16PIN`、`USBLC6-2SC6`、`TP4056`、`RT9080-33GJ5`、
`AO3401`、`AO3400`、`SS14`、`LED-0603`、`10K`、`1k`、`100k`、`200k`、`92J2K4E`(2.4k)、
`CFR-25JR-52-5K1`(5.1k)、`10uf`、`100nF`、`1nF-C0603`、`1uF50V5x11GF`、
`2P-P3.81_KF2EDGV-3.81-2P`、`SS-12F45G4-RS`。

## 自检：网表必须逐网络比对

画完不要只看截图。取 `sch_Netlist.getNetlist()`（**返回 JSON 字符串**），
结构是 `{components: {"<uid>": {props: {Designator}, pinInfoMap: {"<pin>": {net}}}}}`，
据此按网络名汇总引脚，与脚本里写的**期望表**做集合比较，`mismatched` 必须为空。

```
期望：V_SYS: ['D1.1','Q1.2','U4.1','U4.3','C3.1']
实际：由 netlist 汇总
```

注意 netlist 是**异步**的：写完图元立刻读可能拿到上一版，等 ~900ms 再读，
或单独再跑一次只读校验脚本。
