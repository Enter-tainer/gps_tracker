# GPSL0 v3：坐标上下文细化与工程集成报告（`version = 2`, `model_id = 22`）

> **历史基线**：v1 冻结档 `1,171,096 B`（`4.6327 b/pt`，GPZ `8.774x`）；内部未上线过渡稿 v2（`m20`，已合并清理剔除）`1,100,621 B`（`4.3539 b/pt`，GPZ `9.336x`）。
> **结论**：最终发布唯一写入格式 **v3（`version = 2, model_id = 22`）** 全语料 **`1,079,995 B` / `4.2724 b/pt` / GPZ `9.514x`**，相对 v1 **`-91,101 B`（`-7.78%`）**（相对历史 v2 基线 `-20,626 B` / `-1.87%`）；代码、WASM 与文档已全量收敛为 **`v1`（参考/兼容解码）+ `v3`（`model_id = 22`）**，并采用 `u16` 打包概率与计数将 `#![no_std]` 零堆流式编码器体积控在 **`61,888 B`（`60.4 KiB`）**。
> **两件同等重要的事**：① 坐标上下文在格点轨可稳定再挖出 **1.87%**（低量子/全精度轨自动门控为 3,219 槽精简布局）；② 预测器与标志通道方向已被机制性证伪——中值/平滑/相位类预测器一律退步，因为它们破坏的是**精确命中的时间聚集性**，而非命中率。

## 2. v3 核心改动与嵌入式 / 工程集成架构

全部改动均在**概率上下文**与**统一流式工程架构**上：容器（36 B 头 + delta-varint 索引）、12-bit 精确乘法 Range Coder、残差二值化、`coord_mode` 语义与 Sync Seed 与设计冻结点一致；**头部不新增字段**——解码器由 `model_id = 22` 与 `coord_quantum > 10` 自行恢复上下文布局（完整格式见 [`docs/gpsl0_v3_format.md`](./gpsl0_v3_format.md)）。

在 `coord_quantum > 10` 的格点轨上，坐标通道启用以下上下文扩展（`sign` 经 A/B 实测冻结 C2 档）：

1. **`lon` 零标志与幅值因果条件化于本点 `mag4(e_lat)`**（`lon` 幅值从 2 档 `e_lat != 0` 扩为 4 档 `mag4(e_lat)`，单项最大收益 `-4,599 B`）。
2. **`vel_step_bucket` 预测位移速度分档**（5 档 `|v·min(pred_dt, 2·dt_prev)/dt_prev|` 替代裸 `|v|`，`dt_prev == pred_dt` 走免除法快路径）。
3. **`lat`/`lon` 零标志加 3 档加速度符号 `accel_bucket3`**（`|v_prev|` 与 `|v_prev2|` 比较：减速 / 持平 / 加速）。
4. **`lat` 幅值加 `agree_bit` 与 2 档增长标志 `accel_growing`**（`e_lat_prev` 与速度是否同向 + 是否加速）。
5. **`lat`/`lon` 符号扩展为 260 槽**（`(base13 * 4 + mag4(e_prev)) * 5 + vmag_bucket(v_prev)`，`sign_alt` 保持 13 槽，共 **30,805 槽**）。
6. **`coord_quantum <= 10` 量子门控**：全精度与低量子轨（含全部 12 条 `q=1` 轨）自动切换到 `3,219` 槽精简上下文布局，避免长尾噪声轨上下文稀释。

### 工程集成关键决策

- **全面移除过渡模型 `model_id = 20` 并将 `#![no_std]` 流式升级到 `StreamingEncoderV3`（`u16` 打包状态）**：
  - 12-bit 概率恒在 `[4, 4092]`，双速自适应计数只在 `< 2 / < 6 / < 14 / >= 14` 分档；将 `count.min(14)` 存入同一 `u16` 的高 4 位 `(count << 12) | prob` 与独立 `u16 + u8` 逐位数学等价。
  - `30,805` 槽从 `92.4 KiB`（`u16 + u8` + padding）压缩到 **`61,610 B`**，`StreamingEncoderV3` 总结构体 **`61,888 B`（`60.4 KiB`）**。实测当前 `master` 固件（`nrf-sdc + trouble-host`，已移除 S140 SoftDevice）nRF52840 空闲 RAM 为 `120,172 B`（`117.4 KiB`），写入 `.bss` 后仍有约 **`57 KiB`** 余量，未来固件可直接跑通满档 `v3`。
  - 主机 / WASM `encode` 也全部路由到同一套流式核心（按 `coord_quantum > 10` 只在堆上分配 `3,219` 或 `30,805` 项 `u16` 切片，不在栈上构造 62 KB 结构体，同时与研究配置路径 `encode_v2_with_config` 123/123 轨逐字节一致），彻底消除两套编码器维护成本，并将 WASM 产物进一步压小到 **`118,580 B` raw / `47,055 B` gzip**。
- **修复研究分支中 `sign_vmag`/`sign_epmag` 意外失效的死代码门控**：原探索提交中将两者嵌在未启用的旧开关下，实测三档 A/B：
  - C0（仅 13 槽）：`1,082,216 B`（Tier-0 `1,545,916 B`，`30,311` 槽）
  - C1（+`vmag5`，65 槽/轴）：`1,080,360 B`（`-1,856 B`，Tier-0 `1,544,065 B`，`30,415` 槽）
  - **C2（+`vmag5` + `mag4(e_prev)`，260 槽/轴，冻结）**：**`1,079,995 B`**（`-365 B` over C1，Tier-0 **`1,543,700 B`**，共 **`30,805` 槽**）
- **单点真源与按通道内联拆分**：消除编码/解码两份符号推导与四通道重复调用，Rust Native 123 轨解码降至 **`166.85 ms`**、编码降至 **`182.12 ms`**，WASM 编码/解码为 **`214 / 227 ms`**。

## 3. 被证伪的方向：中值 / 平滑预测器（重要）

**原始假设**：格点轨上 `0,1,0,1` 的 Bresenham 锯齿会让二阶预测反向发散，用最近 3 步中值可以消掉。

**离线估计确实支持它**（order-0 残差熵 + 模型代价，q=100 的 1,985,190 点）：

| 预测器 | lat `P(e=0)` | lat 代价 | lon 代价 |
| --- | --- | --- | --- |
| `Tn`（重复上一步增量） | `59.83%` | `1.8684` | `1.9632` |
| `Med3`（最近 3 步增量中值） | **`64.13%`** | **`1.7774`** | **`1.9027`** |
| `Med3` + 低速保持（q≤10） | `61.55%` | `1.8782` | `1.9976` |

**但真实码流上是退步**：

| 配置 | 字节 | `b/pt` | 相对历史 v2 |
| --- | --- | --- | --- |
| 历史 v2（`Tn` + 无新上下文） | `1,102,731` | `4.3623` | — |
| `Med3` 全域替换 | `1,125,894` | `4.4539` | **`+2.10%`** |
| `Med3` + 去掉联合零标志 | `1,120,838` | `4.4339` | `+1.64%` |

**机制**：`Med3` 把**逐轴**命中率从 `59.8%` 提到 `64.1%`，联合全零率从 `35.9%` 提到 `39.7%`，但 `allZero3` 标志的代价反而从 `0.598` 涨到 `0.742 b/pt`（离线）／`0.581 → 0.692`（真实码流）。因为 `Tn` 的命中来自“匀速段重复同一增量”，**成段聚集**，`run_bucket(zero_run)` 上下文几乎免费；`Med3` 的命中是“三点中值恰好相等”，**逐点独立**，长游程消失，游程上下文失效。

**结论**：老结论“平滑会破坏 `e=0` 精确命中”机制说反了——破坏的是**聚集性**，不是命中率。窗口均值、相位累加器（Bresenham）、LMS/ARMA、2D 微旋都是同一机制，可整片跳过。

## 4. 离线熵估计会骗人（方法论结论）

复刻编码器状态机、仅累加条件直方图的离线估计排序在真实码流上多次反转：

| 候选 | 离线估计 | 真实码流 |
| --- | --- | --- |
| `lon_m_cross = 4`（本轮头号收益） | `-0.048 b/pt` | **`-4,599 B`** ✓ |
| 速度幅值 | `-0.038` | **`-9,494 B`** ✓ |
| `lat_m_cross = 2 / 3`（估计器排名第一） | `-0.045` | **`+1,937 / +2,749 B`** ✗ |
| 象限/朝向桶 | `-0.019` | `+5,368 B` ✗ |
| alt「距上次跳变步数+方向」 | `-0.027` | `+819 B` ✗ |

原因：离线探测器会在 `allZero3 == 1` 被真实编码器跳过的点上计费，且无法建模每个上下文槽位从 `0.5` 起步的自适应方差与冷启动代价。真实 Range Coder A/B 扫表是唯一算数的裁判。

## 5. 已确认无效的其它方向

- **JPEG-LS 式游程模式**（`allZero3` 的 `zero_run >= K` 改用游程码）：最好 `+487 B`，标志通道省下的被游程码完整吃掉；逐轨 oracle 也只 `-88 B` ⇒ `az3` 通道在当前架构下已到实用熵下限。
- 14-bit 概率、尾数 bypass、离线静态先验表（5 折 CV `-469 B`）、滑窗 EWMA 活跃度上下文（`+9~13 KB`）、周期性重置概率表、多轨打包（`+35%`）、1e5 格点硬量化到 1e6（`+22%`）。
- **跨轴条件化的反方向**（用上一点 `|e_lon|` 预测 `lat`）：`+1,750 B`。

---

## 6. 剩余空间

- 坐标两通道仍占 `2.578 b/pt`（60%）。若要进一步利用 `|e_lon|` 条件化 `lat`（离线 `-0.048 b/pt`），必须将两个轴的幅值编码交织，属流格式大改而非加维度。
- `alt`（`0.766 b/pt`，高程 1 m 阶梯）：简单上下文维度全部变差，需要游程/阶梯建模。
- `az3`（`0.582 b/pt`）：已到实用下限。
- `q=1` 长尾 12 轨（`11.5524 b/pt`）：受 GNSS 卡尔曼相关噪声与纬度余弦拉伸主导，天花板由噪声底决定。
